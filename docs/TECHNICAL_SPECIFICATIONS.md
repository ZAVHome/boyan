# Техническое задание: Программный комплекс управления цифровой библиотекой «Боян»

---

## 1. Введение и назначение системы

### 1.1. Назначение

Разрабатываемый программный комплекс представляет собой высокопроизводительную, модульную и масштабируемую систему для каталогизации, хранения, обогащения метаданными, веб-чтения и сетевой дистрибуции электронных книг по протоколам **OPDS v1.2** и **OPDS v2.0**.

Система спроектирована по принципу **Strict Headless Backend** с микросервисным разделением: автономный сервер на языке **Go (Golang)** предоставляет исчерпывающий REST API / OpenAPI контракт, а взаимодействие с пользователем осуществляется через специализированные независимые веб-приложения (для ПК и смартфонов), Telegram-ботов и аппаратные читалки (E-Ink ридеры).

### 1.2. Ключевые цели

* **Ультра-низкое потребление ресурсов:** работа бэкенда в пределах 20–50 МБ RAM, мгновенный холодный старт, возможность комфортной работы на слабых VPS, домашних NAS и микрокомпьютерах (Raspberry Pi).
* **Глубокая поддержка русскоязычной литературы и формата FB2/FB2.ZIP:** нативный парсинг вложенных архивов, структурированные серии с индексами, многоуровневое дерево жанров с локализацией, извлечение встроенных обложек без лишней распаковки на диск.
* **Идеальный E-Ink опыт:** поддержка всех поколений читалок (Onyx Boox, PocketBook, Kindle, Kobo) через OPDS и автоконвертацию.
* **Современный UI без компромиссов:** отказ от монолитного устаревшего рендеринга в пользу независимых SPA/PWA фронтендов со строгой поддержкой тем «день/ночь».
* **Многоканальный инжест:** загрузка книг через Web UI, мониторинг файловой системы (`watch-dir`), а также **через чат-ботов Telegram** (отправка файла в чат для мгновенного добавления в библиотеку).

## 3. Функциональные требования к бэкенду (Core Engine)

### 3.1. Технологический стек бэкенда

* **Язык разработки:** Go (Golang) версии 1.23+.
* **База данных:**
  * **По умолчанию:** SQLite 3 с обязательным включением режима `WAL` (Write-Ahead Logging), внешних ключей (`PRAGMA foreign_keys = ON`) и оптимизацией кеша страниц.
  * **Опционально:** PostgreSQL 15+ для высоконагруженных инсталляций.
* **Поисковый движок:** встроенный полнотекстовый поиск SQLite FTS5 с триграммами и стеммингом для русского (`snowball-russian`) и английского языков.
* **Спецификация API:** OpenAPI 3.0 (Swagger UI доступен по адресу `/api/v1/docs`).
* **Формат поставки:** единый статический бинарник без внешних runtime-зависимостей (`CGO_ENABLED=1` для FTS5 или чистый Go с `modernc.org/sqlite`).

### 3.2. Поддержка форматов и метаданных

* **Форматы файлов:**
  * Электронные книги: `FB2`, `FB2.ZIP`, `EPUB`, `MOBI`, `AZW3`, `PDF`, `DJVU`.
  * Архитектурный задел под будущие модули: комиксы (`CBR`, `CBZ`), аудиокниги (`M4B`, `MP3`).
* **Парсинг FB2 / FB2.ZIP:**
  * Прямое чтение архива в памяти / через потоки без предварительной записи распакованного содержимого на диск.
  * Извлечение метаданных FictionBook 2.1+: название, авторы, переводчики, серии и подсерии с дробными/целыми номерами (`number`), аннотации (с очисткой от опасных HTML-тегов), язык, дата публикации, издатель, ISBN.
  * Извлечение бинарной обложки (`<binary id="cover.jpg">`) и генерация уменьшенных превью (WebP / JPEG) на лету с кешированием.
  * Нормализация и перевод технических кодов жанров (например, `sf_history` $\rightarrow$ «Альтернативная история», `popadanec` $\rightarrow$ «Попаданцы») в иерархическую структуру категорий.
* **Многоязычность метаданных:**
  * Автоматическое определение языка книги (ISO 639-1 / 639-2).
  * Возможность фильтрации всего каталога по языкам произведений.
  * Поддержка мультиязычных вариантов написания имён авторов (псевдонимы, оригинальные имена).

### 3.3. Совместимость с Calibre

* Наличие встроенного адаптера импорта из существующих библиотек Calibre:
  * Прямое чтение схемы `metadata.db`.
  * Импорт структуры книг, авторов, серий, тегов и кастомных колонок.
  * Возможность работы в режиме «Calibre Read-Only Mirror» без изменения исходных файлов библиотеки Calibre.

## 4. Спецификация реализации протокола OPDS

Комплекс обязан предоставлять две независимые точки входа для протокола каталогизации:

### 4.1. OPDS v1.2 (Atom/XML)

* **Эндпоинт:** `/opds/v1/feed.xml` (а также персонализированные URL `/opds/v1/user/{token}/feed.xml`).
* **Совместимость:** AlReaderX, KOReader, PocketBook Cloud, FBReader, Moon+ Reader, KyBook.
* **Навигационные каналы (Feeds):**
  1. *По авторам:* с двухуровневой группировкой по алфавиту (Кириллица `А-Я`, Латиница `A-Z`, Символы/Цифры). Внутри автора — группировка: «Книги вне серий», «Серии (по порядку номеров)».
  2. *По сериям / циклам:* упорядоченный список серий с количеством книг и сортировкой книг строго по номеру в серии (`<calibre:series_index>`).
  3. *По жанрам и категориям:* двухуровневое дерево категорий на русском и английском языках (например: «Фантастика» $\rightarrow$ «Боевая фантастика»).
  4. *Новые поступления:* сортировка по дате добавления в библиотеку.
  5. *Популярное и рейтинги:* сортировка по пользовательским оценкам и числу загрузок.
  6. *По языкам:* разбиение на языковые секции (Русский, Английский и др.).
* **Поиск:**
  * Включение дескриптора OpenSearch (`/opds/v1/opensearch.xml`).
  * Поиск по подстроке в названии, авторе, серии или аннотации.
* **Специфика E-Ink:**
  * Оптимизированные ссылки на обложки (атрибуты `rel="http://opds-spec.org/image"` и `rel="http://opds-spec.org/image/thumbnail"`).
  * Корректные MIME-типы: `application/x-fictionbook+xml`, `application/epub+zip`, `application/pdf`.

### 4.2. OPDS v2.0 (JSON-LD)

* **Эндпоинт:** `/opds/v2/catalog.json`.
* **Формат:** современная спецификация на базе Readium Web Publication Manifest.
* **Назначение:** клиенты нового поколения (Thorium Reader, Cantook, мобильные приложения с поддержкой OPDS 2.0).

## 5. Требования к фронтенду и GUI

В соответствии с требованием архитектуры, бэкенд строго отделён от фронтенда. Разрабатываются два специализированных клиента на стеке **Vue 3 (Composition API) / React + Tailwind CSS**:

### 5.1. Требования к UI темам («День / Ночь»)

* **Обязательная поддержка адаптивных цветовых схем:**
  * **Дневной режим (Light Mode):** мягкий контрастный фон без ослепляющей белизны (`#F8FAFC` / `#FFFFFF`), тёмно-серый текст повышенной читаемости.
  * **Ночной режим (Dark Mode):** глубокий тёмно-серый фон (`#0F172A` / `#1E293B`) с пониженной контрастностью ярких элементов для предотвращения усталости глаз.
  * **OLED Black (Pure Black):** абсолютно чёрный фон (`#000000`) для максимального энергосбережения на AMOLED/OLED смартфонах.
  * **Сепия / Бумага (Warm/Sepia):** тёплый оттенок для комфортного вечернего чтения.
* Переключение темы: ручное (тумблер в шапке) + автоматическое (синхронизация с системными настройками ОС `prefers-color-scheme`).

### 5.2. Desktop / Tablet Web Frontend (Интерфейс для ПК и планшетов)

* **Концепция дизайна:** современный медиа-хаб уровня Plex/Spotify с акцентом на полиграфические обложки книг.
* **Основные экраны:**
  1. *Витрина (Home Dashboard):* карусели «Недавние поступления», «Продолжить чтение», «Популярные серии», «Случайный выбор».
  2. *Каталог и фильтры:* сетка карточек с динамическим рендерингом (виртуальный скролл для библиотек от 50 000+ книг), быстрый фильтр по форматам (FB2/EPUB), языку, жанрам, статусу прочтения.
  3. *Карточка книги:* крупная обложка, интерактивные бейджи автора и серии (с переходом в один клик), полное форматированное описание, список доступных файлов с размерами, кнопка онлайн-чтения и скачивания.
  4. *Пакетный редактор метаданных:* массовое присвоение тегов, смена авторов, редактирование серийных номеров для группы выделенных книг.
  5. *Центр импорта и карантина дубликатов:* визуальный drag-and-drop нескольких файлов/архивов, модальное окно сравнения дубликатов (сравнение размеров, форматов, обложек, кнопка «Объединить» / «Заменить» / «Оставить оба»).
* **Встроенный Web-ридер:**
  * Открытие FB2, EPUB и PDF прямо во вкладке браузера.
  * Настройки размера шрифта, межстрочного интервала, полей, цветовой схемы.
  * Автоматическое сохранение прогресса чтения на сервере.

### 5.3. Mobile Web Frontend (PWA для смартфонов)

* **Концепция:** Touch-First PWA с поддержкой установки на рабочий стол (Add to Home Screen) без необходимости установки из магазинов приложений.
* **Особенности взаимодействия:**
  * Управление одной рукой (нижняя навигационная панель: Главная, Поиск, Моя полка, Профиль).
  * Поддержка свайп-жестов (листание глав в читалке, свайп карточки для скачивания).
  * Автономный режим (Service Workers + IndexedDB): возможность сохранить книгу в память браузера смартфона и читать без доступа к сети (в самолёте/метро).
  * Адаптация под E-Ink экраны Android-читалок (высококонтрастный режим без анимаций и градиентов).

## 6. Демон инжеста, файловая система и фоновая обработка

### 6.1. Мониторинг файловой системы (`Watch-Folder Daemon`)

* Использование нативных механизмов ОС (`inotify` в Linux, `FSEvents` в macOS) без циклического polling-сканирования, нагружающего диск.
* Автоматическая реакция на появление файлов и архивов в каталоге `/import` или `/watch`.
* Безопасная пауза перед обработкой (контроль завершения копирования файла по изменению размера/таймауту).

### 6.2. Шаблонизация раскладки файлов на диске

Система должна поддерживать настраиваемый движок именования и распределения файлов библиотеки по дисковым папкам с поддержкой макросов:

* Шаблон по умолчанию (Calibre-style):  
  `{LibraryRoot}/{Author}/{Title} ({BookID})/{Title} - {Author}.{ext}`
* Альтернативный читаемый шаблон (Media-server style):  
  `{LibraryRoot}/{Author}/{Series}/{SeriesIndex:02d} - {Title}.{ext}`
* Корректная санитизация: автоматическая транслитерация или удаление запрещённых спецсимволов ОС (`<>:"/\|?*`).

### 6.3. Интеллектуальный контроль дубликатов («Карантин»)

* Алгоритм выявления дубликатов:
  1. *Точное совпадение хеша (SHA-256):* мгновенный пропуск или прикрепление существующей записи без повторного копирования.
  2. *Нечёткое совпадение метаданных:* нормализованное сравнение `Автор + Название` (удаление знаков препинания, приведение к нижнему регистру, сравнение алгоритмом Левенштейна / Jaro-Winkler).
* Действия при совпадении:
  * Если формат уже есть в книге: перемещение в очередь **«Карантин дубликатов»** в админ-панели с фиксацией размеров (существующий vs новый).
  * Если формата нет (например, в базе был только EPUB, а пришёл FB2): автоматическое прикрепление нового формата к существующей карточке книги.

## 7. Внешние интеграции и чат-боты

### 7.1. Telegram-бот двустороннего действия (Ingest & Delivery)

Бот является официальным компонентом комплекса и выполняет две ключевые функции:

#### 1. Входящий импорт (Inbound Ingestion)

* Пользователь (авторизованный по Telegram ID) отправляет боту файл книги (`.fb2`, `.zip`, `.epub`, `.mobi`) или ссылку на скачивание.
* Бот передаёт файл в ядро системы через внутренний REST API.
* Ядро парсит книгу, обогащает обложкой и метаданными, помещает в библиотеку и возвращает боту карточку книги с подтверждением успешного добавления:
  > *«Книга "Спасти СССР" (Валерий Большаков) успешно добавлена в библиотеку! Серия: Квинт Лициний #5. Жанры: Попаданцы, Альтернативная история.»*

#### 2. Поиск и доставка (Search & Delivery)

* Инлайн-поиск книг прямо в чате Telegram: `@my_book_bot НазваниеКниги`.
* Просмотр карточки, аннотации и обложки книги.
* Кнопка *«Скачать»* (выбор формата FB2/EPUB/MOBI) с мгновенной отправкой файла книги прямо в чат Telegram для открытия на смартфоне.
* Кнопка *«Отправить на Kindle / PocketBook»* (через SMTP шлюз).

### 7.2. Автообогащение метаданных (Metadata Providers)

* Модульная архитектура внешних скраперов с приоритетами источников:
  1. **FantLab (Лаборатория Фантастики):** наивысший приоритет для русскоязычной фантастики/фэнтези (точные составы авторских циклов, хронологический порядок серий, профессиональные аннотации).
  2. **LiveLib / Litres:** жанры, читательские рейтинги, высококачественные сканы обложек.
  3. **OpenLibrary / Google Books:** международные издания, ISBN, оригинальные названия зарубежных авторов.
* Настраиваемый режим: *Автоматический* (при инжесте книги) или *Полуавтоматический* (выбор лучшего варианта в карточке книги через Web UI).

### 7.3. Конвертация форматов

* Интеграция с консольными утилитами `ebook-convert` (Calibre engine) и `kepubify`.
* Фоновая конвертация и конвертация «на лету» (по запросу E-Ink читалки при скачивании по OPDS).

## 8. Аутентификация, права доступа и безопасность

### 8.1. Ролевая модель (RBAC)

1. **Администратор (Admin):** полный доступ к настройкам сервера, каталогам инжеста, одобрению дубликатов в карантине, управлению пользователями.
2. **Пользователь (User):** личный кабинет, персональные полки («Читаю сейчас», «Прочитано», «Избранное»), отслеживание прогресса чтения, скачивание и онлайн-чтение, привязка личного Telegram ID.
3. **Гость / Ребёнок (Restricted User):** ограниченный доступ. Применение правил **родительского контроля** (автоматическое сокрытие книг по запрещённым тегам или возрастным меткам `18+`).

### 8.2. Механизмы авторизации

* **Web UI (SPA/PWA):** `JWT Bearer Tokens` в защищённых `HttpOnly SameSite=Lax` cookie.
* **OPDS читалки (E-Ink):**
  * `HTTP Basic Authentication` (логин и пароль пользователя).
  * `Personal Feed Tokens` (уникальный защищённый токен в URL ленты, например: `/opds/v1/feed.xml?token=a8f9c1...`, что позволяет настраивать читалку без ввода сложных паролей с экранной клавиатуры E-Ink ридера).

## 9. Требования к развертыванию, упаковке и DevOps

### 9.1. Контейнеризация (Docker Compose)

Система поставляется с готовым файлом `docker-compose.yml`, обеспечивающим запуск комплекса в изолированных контейнерах:

1. `opds-core`: Go бэкенд (порт 8080).
2. `opds-web-desktop`: Nginx-контейнер со статикой десктопного фронтенда.
3. `opds-web-mobile`: Nginx-контейнер с PWA мобильного фронтенда.
4. `opds-telegram-bot`: сервис Telegram-бота.
5. Реверс-прокси (Nginx/Traefik) для маршрутизации трафика (например, `/api/*` и `/opds/*` на core, мобильные user-agent на мобильный фронт, остальные на десктопный).

### 9.2. Автономная установка (Bare-Metal)

* Возможность работы без Docker: единый скомпилированный бинарный файл `opds-server` под архитектуры `linux/amd64`, `linux/arm64`, `windows/amd64`.
* Конфигурация через единый файл `config.yaml` или переменные окружения (стандарт 12-Factor App).
* Автоматическое применение миграций базы данных при старте бинарника.
* Встроенный планировщик резервного копирования базы данных (SQLite online backup `VACUUM INTO '/backups/backup.db'`).
