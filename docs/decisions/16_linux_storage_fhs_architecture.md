# ADR 16: Архитектура размещения данных на Linux (FHS 3.0 и управление дисковым пространством)

**Дата:** 17 сентября 2026 г.  
**Статус:** Утверждено  
**Авторы:** Команда проекта «Боян» (Boyan)

---

## 1. Контекст и проблематика

При промышленном развертывании серверного комплекса «Боян» на серверах и виртуальных машинах (VPS) под управлением Linux возникает вопрос стандартизации файловых путей в соответствии со стандартом **FHS (Filesystem Hierarchy Standard 3.0)** и практикой системного администрирования.

Данные, которыми оперирует «Боян», принципиально разделяются на два различных класса:

1. **Класс А: Системное состояние и метаданные (State & Metadata)**
   - База данных SQLite 3 (`boyan.db`), файлы журнала упреждающей записи (`boyan.db-wal`, `boyan.db-shm`).
   - Индексы полнотекстового поиска FTS5 со стеммингом.
   - Очередь карантина (`quarantine/`) для файлов с ошибками и дубликатов.
   - Характер нагрузки: транзакционный ввод-вывод (I/O), размер от десятков мегабайт до нескольких гигабайт.

2. **Класс Б: Книжный массив (Library Content Payload)**
   - Физические файлы электронных книг: FB2, FB2.ZIP, EPUB, MOBI, PDF, DJVU.
   - Характер нагрузки: чтение потоков, размер от десятков гигабайт до сотен гигабайт и терабайтов (например, архив «Флибуста» или «Либрусек» весит 400–600+ ГБ).

### Проблема

На типовых VPS/VDS системный раздел `/` (включающий `/var/`) часто выделяется на относительно небольшом, но быстром диске (20–50 ГБ NVMe под операционную систему). Крупные библиотеки размещаются на отдельных томах (Block Storage, NFS, SMB или отдельный HDD/SSD).  
Если закрепить каталог библиотеки жестко за `/var/lib/boyan/books`, пользователи с крупными коллекциями рискуют полностью переполнить корневой раздел (`100% disk full`), что парализует работу операционной системы (падение `systemd-journald`, блокировка временных файлов, отказ системных сервисов).

## 2. Рассмотренные альтернативы

### Вариант 1: Монолитное хранение всего в `/var/lib/boyan/` (Без разделения)

- **Суть:** База данных, карантин, импорт и книги лежат строго внутри `/var/lib/boyan/`.

- **Плюсы:** Все файлы сервиса собраны в одной директории, простота написания базового скрипта установки.
- **Минусы:** Высокий риск переполнения корневого раздела системы при загрузке тяжелых архивов книг. Затруднено монтирование внешних блочных хранилищ без создания костылей в виде символических ссылок.
- **Вердикт:** Отклонено как безальтернативный вариант.

### Вариант 2: Принудительный вынос книг в `/srv/books` или `/mnt/storage`

- **Суть:** Запрет хранения книг в `/var/lib/` и обязательное указание внешнего каталога.

- **Плюсы:** Корневой раздел `/var` гарантированно защищен.
- **Минусы:** Нарушение принципа «работает из коробки» для компактных домашних установок (до 10–20 ГБ), где сервер имеет единый диск. Усложнение первого запуска для неискушенных пользователей.
- **Вердикт:** Отклонено как жесткое ограничение.

### Вариант 3: Гибридная FHS-архитектура с четким разделением State и Content (Выбранный вариант)

- **Суть:**
  1. Служебное состояние (база данных, WAL, карантин) закрепляется за `/var/lib/boyan/` в соответствии со стандартом FHS.
  2. Временные обложки и превью выносятся в `/var/cache/boyan/covers/`.
  3. Каталог библиотеки (`library_dir`) является полностью конфигурируемым:
     - По умолчанию в шаблонном конфиге предлагается `/var/lib/boyan/library` (для компактных инсталляций на одном диске).
     - Для средних и крупных коллекций в документации и комментариях предоставляется явное руководство по монтированию отдельного тома в `/srv/books` или `/mnt/storage/books`, либо пробросу симлинка.

- **Вердикт:** Принято единогласно.

## 3. Архитектурная карта каталогов «Бояна» (FHS 3.0)

| Путь в ОС Linux | Назначение по FHS | Владелец и права | Ротация и бэкап |
| :--- | :--- | :--- | :--- |
| **`/opt/boyan/boyan`** | Исполняемый бинарный файл сервиса | `boyan:boyan`, `0755` | Обновляется при релизах |
| **`/opt/boyan/config.yaml`** (или `/etc/boyan/`) | Конфигурация комплекса | `boyan:boyan`, `0640` | Резервное копирование |
| **`/var/lib/boyan/data/boyan.db`** | База данных SQLite 3 + WAL + FTS5 | `boyan:boyan`, `0640` | Ежесуточный hot-backup через `sqlite3 .backup` |
| **`/var/lib/boyan/data/quarantine/`** | Карантин дубликатов и поврежденных файлов | `boyan:boyan`, `0750` | Модерируется админом |
| **`/var/cache/boyan/covers/`** | Кэш сгенерированных миниатюр обложек | `boyan:boyan`, `0750` | Исключается из бэкапа, очищается при необходимости |
| **`/var/lib/boyan/import/`** | Каталог горячего мониторинга (`fsnotify`) | `boyan:boyan`, `0770` | Входящий буфер заливки |
| **`/var/lib/boyan/library/`** *(default)* или **`/srv/books`** / **`/mnt/storage/books`** | Постоянное структурированное хранилище книг | `boyan:boyan`, `0755` | Основной массив хранения |
| **`/var/www/boyan/`** | Статика SPA/PWA фронтендов (`desktop`, `mobile`) | `www-data:www-data`, `0755` | Отдаются напрямую Nginx |

## 4. Интеграция с systemd и изоляция

Для сервиса `boyan.service` задействуются нативные декларативные директивы systemd:

```ini
[Service]
User=boyan
Group=boyan

# Нативное управление жизненным циклом каталогов FHS:
# systemd автоматически создаст и выставит права 0750 на /var/lib/boyan и /var/cache/boyan
StateDirectory=boyan
CacheDirectory=boyan

# Защита операционной системы:
# /usr, /boot, /etc монтируются только для чтения; /var/lib, /srv, /mnt доступны для записи
ProtectSystem=full
ProtectHome=true
NoNewPrivileges=true
PrivateTmp=true
```

## 5. Сценарии подключения хранилища книг

### Сценарий 1: Небольшая библиотека на одном диске (до 20 ГБ)

Используются стандартные пути из `install.sh`:

- Книги хранятся в `/var/lib/boyan/library/`.
- Заливка через `/var/lib/boyan/import/`.
- Никаких дополнительных настроек дисков не требуется.

### Сценарий 2: Подключение внешнего блочного тома (Volume 100+ ГБ)

1. Монтирование тома в `/srv/books` (или `/mnt/storage/books`):

   ```bash
   sudo mkdir -p /srv/books
   sudo mount /dev/sdb1 /srv/books
   # Добавление в /etc/fstab для автоподключения при загрузке:
   # /dev/sdb1 /srv/books ext4 defaults,noatime 0 2
   sudo chown -R boyan:boyan /srv/books
   sudo chmod -R 755 /srv/books
   ```

2. Настройка в `/opt/boyan/config.yaml`:

   ```yaml
   storage:
     library_dir: "/srv/books"
     watch_dir: "/srv/books/import"
   ```

   *Либо через симлинк:*

   ```bash
   sudo ln -s /srv/books /var/lib/boyan/library
   ```

## 6. Регламент резервного копирования

Благодаря разделению FHS резервное копирование разделяется на две независимые процедуры:

1. **Горячий бэкап базы данных (быстро, по расписанию):**

   ```bash
   sqlite3 /var/lib/boyan/data/boyan.db ".backup '/var/lib/boyan/data/boyan_backup_$(date +%F).db'"
   ```

   Выполняется без остановки сервера благодаря режиму SQLite WAL.
2. **Бэкап книжного массива (фоново через rsync/restic):**

   ```bash
   rsync -av --delete /srv/books/ backup-server:/backups/boyan-books/
   ```

3. **Кэш (`/var/cache/boyan/`)** полностью исключается из резервных копий (`--exclude='/var/cache/boyan'`).

## 7. Последствия и влияние на кодовую базу

1. **`config.example.yaml`:** Дополнен подробными комментариями о разделении State (`/var/lib/boyan/`) и Payload (`/srv/books` или `/var/lib/boyan/library`).
2. **`scripts/installer/install.sh`:** Создает правильную иерархию `/var/lib/boyan/{data,library,import}` и `/var/cache/boyan/covers`.
3. **`scripts/systemd/boyan.service`:** Включает директивы `StateDirectory=boyan` и `CacheDirectory=boyan`.
4. **Документация:** Руководства по установке (`docs/vps_installation_guide_ru.md` и `docs/vps_installation_guide_en.md`) содержат детальные инструкции по подключению внешних дисков.
