# Архитектурное решение № 17: Архитектура панели администратора («Админка») комплекса «Боян»

**Дата:** 17 сентября 2026 г.  
**Статус:** Утверждено  
**Область:** Backend (Go REST API), Frontend (`web-desktop` SPA), DevSecOps / System Administration  

---

## 1. Контекст и проблематика

На предыдущих этапах (1–6) в комплексе «Боян» были реализованы:

- Ядро каталогизации и стриминга книг (SQLite WAL + FTS5, FB2/ZIP/EPUB/MOBI/PDF/DJVU);
- Шлюзы OPDS v1.2 и OPDS v2.0;
- REST API Gateway с базовой JWT-аутентификацией;
- Веб-интерфейсы `web-desktop` и `web-mobile` (PWA);
- Мониторинг входящей папки (`fsnotify`) и карантин дубликатов;
- Импорт сторонних библиотек Calibre (`metadata.db`) и двусторонний Telegram-бот.

Однако функции администрирования оставались фрагментированными:

- Управление пользователями ограничивалось лишь созданием дефолтного администратора при первом запуске;
- Отсутствовала возможность редактирования метаданных книг (исправление опечаток в авторах, жанрах, сериях) и удаления поврежденных/ненужных книг из каталога;
- Отсутствовал визуальный интерфейс управления хранилищем и принудительным сканированием библиотечных директорий;
- Не было системного мониторинга состояния хоста (RAM, CPU, диск библиотеки), метрик базы данных SQLite (WAL, размер, чекпоинты), кэша обложек и логов сервера;
- Долгие операции (рескан, импорт Calibre) блокировали HTTP-запрос без индикации прогресса.

---

## 2. Согласованные архитектурные решения

На основе интерактивного проектирования (`/grill-me`) согласованы следующие архитектурные принципы:

### 2.1. Размещение и UI Layout (Фронтенд)

1. **Единое SPA-приложение:** Панель администратора встраивается в существующий проект `frontends/web-desktop` в виде защищенного роута `/admin` (доступ только пользователям с `role: "admin"`).
2. **Dedicated Admin Layout:** Выделенный полноэкранный рабочий интерфейс со специализированным компактным боковым меню (Дашборд, Пользователи, Каталог книг, Карантин, Хранилище и сканер, Настройки, Системные логи) и быстрой кнопкой «Вернуться в библиотеку».
3. **Двусторонний доступ к редактированию книг:**
   - Полнофункциональная таблица управления книгами в `/admin/books` (фильтры, поиск, пагинация, пакетные действия);
   - Контекстная кнопка «Редактировать» в модальном окне/карточке книги пользовательского каталога (видна только авторизованному администратору).
4. **Темы и интернационализация:** Полная поддержка дизайн-системы (Light, Dark, OLED Black, Sepia) и двуязычия через `vue-i18n` (RU / EN).

### 2.2. Функциональные модули админки

#### Модуль 1: Системный дашборд и мониторинг

- **Метрики хоста и среды:** Потребление оперативной памяти (RAM Allocated, Sys, Heap, Total), использование диска хранилища (Total, Free, Used %), аптайм сервера, количество горутин и версия Go.
- **Статистика библиотеки:** Общее число книг, уникальных авторов, серий, суммарный размер библиотеки на диске, круговая диаграмма распределения по форматам (FB2, FB2.ZIP, EPUB, MOBI, PDF, DJVU).
- **База данных SQLite:** Размер файла БД и WAL-файла, статистика полнотекстового индекса FTS5, кнопка ручного запуска `PRAGMA wal_checkpoint(TRUNCATE)` и `VACUUM`.
- **Кэш обложек:** Размер папки кэша на диске, количество сгенерированных миниатюр, кнопка безопасной очистки кэша (`Purge Cover Cache`).
- **Telegram-бот:** Индикатор статуса (Активен / Остановлен / Ошибка токена), имя бота, режим работы (Long Polling / Webhook).
- **Системный журнал (Log Viewer):** Просмотр последних 200 логов из кольцевого буфера памяти (`slog`), фильтрация по уровням `INFO`, `WARN`, `ERROR`, поиск по ключевым словам.

#### Модуль 2: Управление пользователями и политикой регистрации

- **Гибридный режим регистрации:**
  - Ручное создание пользователей администратором через админку (логин, пароль, выбор роли: `admin`, `user`, `restricted`, статус: активен/заблокирован);
  - Глобальная опция в настройках: «Разрешить самостоятельную регистрацию новых пользователей» (вкл/выкл).
- **Операции над пользователями:** Смена роли, смена/сброс пароля, блокировка/разблокировка (деактивация), удаление (за исключением текущего авторизованного админа).

#### Модуль 3: Управление книгами и метаданными (Кураторство каталога)

- **Редактор метаданных:** Редактирование названия книги, списка авторов, серий и номеров в серии, жанровых кодов, языка, аннотации, загрузка новой обложки.
- **Политика удаления книг:** Модальное окно подтверждения с явным выбором:
  1. *«Удалить только из базы данных»* (файлы остаются на диске);
  2. *«Удалить из базы данных и безвозвратно стереть файлы книги с диска»* (исключает повторный автоинжест сканером).
- **Расширенные пакетные операции (Batch Actions):** Выбор нескольких книг чекбоксами и массовые операции:
  - Массовое удаление (с выбором политики очистки диска);
  - Массовое добавление / смена жанра;
  - Массовое назначение автора / серии;
  - Массовая регенерация миниатюр обложек.

#### Модуль 4: Хранилище, сканер и фоновые задачи (Task Manager)

- **Управление сканером:** Кнопка ручного запуска полного рескана папки входящих (`watch_dir`) и библиотеки (`library_dir`), статус `fsnotify`.
- **Асинхронный менеджер задач (Task Manager):**
  - Длительные операции (рескан, импорт Calibre, пакетная регенерация обложек) выполняются в фоне в пуле воркеров;
  - Клиент опрашивает `GET /api/v1/admin/tasks/{id}` (polling) с отображением прогресс-бара (`processed`, `total`, `current_item`, `errors`, `status: pending|running|completed|failed`).

#### Модуль 5: Модерация карантина дубликатов

- Интеграция текущей очереди карантина в структуру админки.
- Сравнение версий (разрешение конфликтов: замена существующего файла, пропуск входящего, сохранение обоих как разных изданий).
- Пакетное одобрение / удаление дубликатов.

#### Модуль 6: Конфигурация сервера (Settings)

- Чтение и веб-редактирование параметров из `config.yaml` (каталоги, лимиты, настройки OPDS, параметры безопасности, токен Telegram-бота).
- Перезапись файла конфигурации на диске.
- Кнопка «Применить и перезапустить фоновые службы» (перезапуск watcher, Telegram-бота и сброс кэша).

## 3. Схема REST API администратора

Все эндпоинты требуют авторизации с ролью администратора (`RequireAdmin`):

```
# Системный мониторинг и дашборд
GET    /api/v1/admin/dashboard/stats        — Сводные метрики библиотеки, форматы, диски
GET    /api/v1/admin/system/host            — Метрики хоста (RAM, CPU, Goroutines, Disk Free)
GET    /api/v1/admin/system/database        — Метрики SQLite (размер db, wal, FTS5)
POST   /api/v1/admin/system/database/vacuum — Запуск SQLite WAL checkpoint / VACUUM
GET    /api/v1/admin/system/cache           — Метрики кэша обложек
POST   /api/v1/admin/system/cache/purge     — Полная или выборочная очистка кэша обложек
GET    /api/v1/admin/system/logs            — Чтение кольцевого буфера логов (tail N)

# Управление пользователями
GET    /api/v1/admin/users                  — Список пользователей (пагинация, фильтр по роли)
POST   /api/v1/admin/users                  — Создание нового пользователя
GET    /api/v1/admin/users/{id}             — Детальная информация о пользователе
PUT    /api/v1/admin/users/{id}             — Редактирование пользователя (роль, статус активности)
PUT    /api/v1/admin/users/{id}/password    — Сброс/установка пароля администратором
DELETE /api/v1/admin/users/{id}             — Удаление пользователя

# Управление книгами
GET    /api/v1/admin/books                  — Табличный реестр книг (фильтры, сортировка)
PUT    /api/v1/admin/books/{id}             — Обновление метаданных книги
DELETE /api/v1/admin/books/{id}             — Удаление книги (?delete_files=true|false)
POST   /api/v1/admin/books/{id}/cover       — Ручная замена/регенерация обложки
POST   /api/v1/admin/books/batch            — Пакетные действия (batch delete, batch tag, batch cover)

# Сканер и фоновые задачи (Task Manager)
POST   /api/v1/admin/scanner/run            — Запуск фонового рескана хранилища -> возвращает task_id
GET    /api/v1/admin/tasks                  — Список активных и завершенных фоновых задач
GET    /api/v1/admin/tasks/{id}             — Статус фоновой задачи (polling прогресса)
POST   /api/v1/admin/tasks/{id}/cancel      — Отмена фоновой задачи

# Конфигурация и управление службами
GET    /api/v1/admin/settings               — Получение текущих параметров config.yaml
PUT    /api/v1/admin/settings               — Сохранение обновленной конфигурации в config.yaml
POST   /api/v1/admin/services/reload        — Горячий перезапуск фоновых сервисов (watcher, tg-bot)

# Публичная регистрация (если включена в настройках)
POST   /api/v1/auth/register                — Самостоятельная регистрация (публичный эндпоинт)
```

## 4. Архитектура фонового менеджера задач (Task Manager)

```
┌─────────────────┐      HTTP POST /admin/scanner/run      ┌──────────────────────┐
│  Admin Web UI   │ ─────────────────────────────────────> │  Admin Task Handler  │
│  (Vue 3 / Vite) │                                        └──────────┬───────────┘
│                 │                                                   │ Spawns Task
│                 │      HTTP GET /admin/tasks/{id}                   ▼
│                 │ <───────────────────────────────────── ┌──────────────────────┐
│   Polling 1s    │      { progress: 42%, status: ... }    │     Task Manager     │
│                 │                                        │  (In-Memory + Mutex) │
│                 │                                        └──────────┬───────────┘
│                 │                                                   │ Progress updates
│                 │                                                   ▼
│                 │                                        ┌──────────────────────┐
│                 │                                        │ Scanner / Worker Go  │
└─────────────────┘                                        └──────────────────────┘
```

Каждая задача описывается структурой:

- `ID` (UUID)
- `Type` (`scan_library`, `import_calibre`, `batch_cover_regen`, `vacuum_db`)
- `Status` (`pending`, `running`, `completed`, `failed`, `cancelled`)
- `Progress` (0–100%)
- `ProcessedCount`, `TotalCount`
- `CurrentItem` (имя текущего обрабатываемого файла)
- `Errors` (список ошибок обработки)
- `CreatedAt`, `StartedAt`, `FinishedAt`

## 5. Итоги и соответствие стандартам

Данное решение:

- Сохраняет Headless-архитектуру: сервер предоставляет строго документированные REST-эндпоинты через OpenAPI 3.0;
- Соответствует стандартам безопасности: доступ строго ограничен `RequireAdmin`;
- Обеспечивает безопасное обращение с файловой системой при удалении книг (защита от случайной потери файлов);
- Предоставляет системным администраторам и владельцам домашних серверов полную прозрачность и контроль над комплексом «Боян».
