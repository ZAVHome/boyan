# Сравнительный анализ HTTP-роутеров для Go бэкенда (Boyan / Next-Gen OPDS Suite)

## 1. Контекст и архитектурные ограничения проекта

В рамках проекта **Next-Gen OPDS Suite** к бэкенду предъявляются строгие требования ([docs/TECHNICAL_SPECIFICATIONS.md](file:///d:/git/AntiGravity/boyan/docs/TECHNICAL_SPECIFICATIONS.md), [GEMINI.md](file:///d:/git/AntiGravity/boyan/GEMINI.md)):
1. **Ультра-низкое потребление RAM:** 20–50 МБ оперативной памяти для комфортной работы на слабых VPS, домашних NAS и микрокомпьютерах (Raspberry Pi).
2. **Стриминг бинарных данных:** прямая отдача файлов книг из FB2.ZIP архивов через `io.Copy` / `w.Write()` без буферизации всего файла в памяти.
3. **Генерация динамических фидов OPDS v1.2 (XML) и v2.0 (JSON-LD):** отдача с корректными MIME-типами, заголовками кеширования (`ETag`, `Last-Modified`) и поддержкой `Range requests`.
4. **Документирование OpenAPI 3.0 / Swagger UI:** полная интеграция с аннотациями `swag`.
5. **Логирование и трассировка:** структурированное логирование через нативный `log/slog` (Go 1.21+).

Ниже представлен детальный сравнительный анализ трёх кандидатов:
- **Вариант 1:** `go-chi/chi/v5`
- **Вариант 2:** `labstack/echo/v4`
- **Вариант 3:** Стандартная библиотека `net/http` (Go 1.22+)

## 3. Детальный разбор каждого варианта

### Вариант 1: `go-chi/chi/v5`

`chi` — это не монолитный фреймворк, а легковесный компонуемый роутер, построенный на префиксном дереве (radix tree).

#### Преимущества:
1. **100% совместимость с `net/http`:** Любой обработчик в `chi` — это стандартный `func(w http.ResponseWriter, r *http.Request)`. Нет вендорлока на кастомные контексты фреймворка.
2. **Модульность суб-роутеров:**
   В проекте требуется строгое разделение:
   - `/api/v1/...` (REST JSON API с JWT авторизацией)
   - `/opds/v1/...` (XML Atom с поддержкой Basic Auth и URL-токенов)
   - `/opds/v2/...` (JSON-LD с поддержкой Readium спецификации)
   `chi` позволяет элегантно изолировать эти ветви через `r.Route("/opds/v1", func(r chi.Router) { ... })` с независимыми цепочками middleware.
3. **Безупречный стриминг файлов:** Потоковое чтение из ZIP-архива в `w` делается одной строкой `io.Copy(w, zipFileReader)` без вмешательства промежуточных буферов фреймворка.
4. **Контекст Go 1.20+:** Параметры URL (`chi.URLParam(r, "id")`) извлекаются прямо из стандартного `r.Context()`.

#### Недостатки:
- Нет встроенного механизма валидации структур из коробки (но в идиоматичном Go для этого используется `go-playground/validator` или ручная валидация в DTO, что чище и надежнее).

---

### Вариант 2: `labstack/echo/v4`

`echo` — полнофункциональный микрофреймворк, очень популярный в Go благодаря удобству написания REST API.

#### Преимущества:
1. Очень лаконичный синтаксис для JSON API: `c.JSON(http.StatusOK, book)`, `c.Bind(&req)`.
2. Готовые middleware из коробки (CORS, JWT, Gzip, RateLimiter).
3. Высокая скорость маршрутизации.

#### Недостатки:
1. **Кастомный `echo.Context`:** Все обработчики завязаны на сигнатуру `func(c echo.Context) error`. Это отрывает кодовую базу от стандартной библиотеки.
2. **Сложность для не-JSON эндпоинтов (OPDS XML и стриминг):** Чтобы отдать потоковый XML или простримить байты из ZIP, приходится либо обходить абстракцию `echo`, обращаясь к `c.Response().Writer`, либо использовать `c.Stream()`.
3. **Транзитивные зависимости:** Привносит сторонние пакеты (`fasttemplate` и др.), увеличивая размер бинарника.
4. **Собственный логер:** До версии Echo v5 интеграция с `log/slog` требует адаптеров.

---

### Вариант 3: Стандартный `net/http` (Go 1.22+)

В Go 1.22 стандартный `http.ServeMux` получил поддержку методов HTTP и шаблонов путей (например, `GET /api/v1/books/{id}`).

#### Преимущества:
1. Полное отсутствие внешних зависимостей (`go.mod` чист от сторонних роутеров).
2. Максимальная надежность и поддержка от команды Go.
3. Минимальный возможный размер исполняемого файла.

#### Недостатки:
1. **Слабая поддержка middleware для групп маршрутов:** В `net/http` нет концепции групп маршрутов (sub-routers) с изолированными middleware. Чтобы применить JWT авторизацию только к `/api/v1/admin/*`, а Basic Auth к `/opds/v1/*`, придется либо писать собственные каскадные мультиплексоры, либо оборачивать каждый хэндлер вручную.
2. **Отсутствие готового стека middleware:** Придётся с нуля писать middleware для генерации `Request-ID`, восстановления после паники (`Recoverer`), замера времени ответа, CORS и таймаутов.
3. **Больше шаблонного кода (boilerplate):** Извлечение параметров пути `r.PathValue("id")` работает, но композиция больших REST + OPDS API с десятками эндпоинтов превращается в громоздкий код.

## 4. Сравнительный пример кода хэндлера стриминга книги

### В `chi`:
```go
func (h *BookHandler) StreamBook(w http.ResponseWriter, r *http.Request) {
    bookID := chi.URLParam(r, "id")
    fileReader, format, err := h.service.GetBookStream(r.Context(), bookID)
    if err != nil {
        http.Error(w, err.Error(), http.StatusNotFound)
        return
    }
    defer fileReader.Close()

    w.Header().Set("Content-Type", format.MimeType())
    w.Header().Set("Content-Disposition", fmt.Sprintf(`attachment; filename="%s"`, format.Filename()))
    
    // Прямой потоковый сброс без буферизации в RAM
    io.Copy(w, fileReader)
}
```

### В `echo`:
```go
func (h *BookHandler) StreamBook(c echo.Context) error {
    bookID := c.Param("id")
    fileReader, format, err := h.service.GetBookStream(c.Request().Context(), bookID)
    if err != nil {
        return echo.NewHTTPError(http.StatusNotFound, err.Error())
    }
    defer fileReader.Close()

    return c.Stream(http.StatusOK, format.MimeType(), fileReader)
}
```

## 5. Итоговый вывод и утвержденное решение

> [!TIP]
> **Утвержденное решение: `go-chi/chi/v5`**

### Почему именно `chi` утвержден для Boyan (Next-Gen OPDS Suite):
1. **Архитектурная чистота:** Проект сочетает в себе **три разных типа протоколов**:
   - REST JSON API (для Vue 3 фронтендов)
   - XML/Atom feed (для читалок OPDS 1.2)
   - Readium JSON-LD feed (для читалок OPDS 2.0)
   `chi` позволяет построить четкую древовидную структуру без навязывания единой модели сериализации `echo.Context`.
2. **Соблюдение жесткого бюджета памяти (20–50 МБ RAM):** У `chi` нулевой оверхед по памяти, он не выделяет лишних аллокаций на каждый запрос, что критически важно для работы на E-Ink устройствах и микро-серверах.
3. **Безупречная интеграция с `log/slog`:** Легко пишется структурированное логирование с фиксацией длительности запроса, статус-кода и байтов ответа.
4. **Удобный WSL2/Linux деплой:** Статический бинарник Go с `chi` и `modernc.org/sqlite` весит всего ~15–20 МБ и не требует ни единой внешней C-библиотеки.
