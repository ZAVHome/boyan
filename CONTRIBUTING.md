# Руководство по участию в разработке (Contributing Guide)

Спасибо за ваш интерес к развитию **Next-Gen OPDS Suite (Boyan)**! Этот проект развивается с открытым исходным кодом, и мы приветствуем любые улучшения, предложения и исправления ошибок.

---

## 1. Архитектурные принципы

Перед началом разработки ознакомьтесь с ключевыми принципами проекта:
- **Strict Headless Architecture:** Go-бэкенд отвечает исключительно за REST API и OPDS v1.2 / v2.0 протоколы. Бэкенд не содержит монолитных HTML-шаблонов.
- **Два фронтенда:**
  - `web-desktop`: Vue 3 + Tailwind CSS для ПК и планшетов.
  - `web-mobile`: Vue 3 + Tailwind CSS Touch-first PWA с поддержкой офлайн-чтения и E-Ink экранов.
- **Поддержка тем:** Light, Dark, OLED Black и Sepia обязательны для любого фронтенда.
- **Локализация:** Тексты фронтенда должны использовать `vue-i18n` (русский и английский языки).
- **Архитектурные решения (ADR):** Любые крупные архитектурные изменения должны фиксироваться в виде документов в директории `docs/decisions/`.

## 2. Процесс разработки (Development Workflow)

1. **Форк и клонирование:**
   ```bash
   git clone https://github.com/ZAVHome/boyan.git
   cd boyan
   ```

2. **Создание ветки:**
   Создавайте ветку с префиксом типа изменения:
   ```bash
   git checkout -b feature/awesome-feature
   # или
   git checkout -b fix/parser-zip-handling
   ```

3. **Локальный запуск:**
   - Скопируйте `config.example.yaml` в `config.yaml`.
   - Запустите бэкенд: `make run-backend`
   - Запустите десктопный фронтенд: `make run-desktop` (порт 3000)
   - Запустите мобильный фронтенд: `make run-mobile` (порт 3001)

4. **Запуск тестов:**
   ```bash
   make test
   ```
   Убедитесь, что все тесты бэкенда (`go test -v -race ./...`) и фронтендов проходят успешно.

## 3. Стандарты коммитов (Conventional Commits)

Мы используем соглашение [Conventional Commits](https://www.conventionalcommits.org/):
- `feat:` — новая функциональность
- `fix:` — исправление ошибки
- `docs:` — изменения в документации
- `chore:` — вспомогательные задачи, обновление зависимостей, версионирование
- `refactor:` — рефакторинг кода без изменения внешней логики
- `test:` — добавление или исправление тестов
- `ci:` — изменения в скриптах сборки и CI/CD

Пример:
```text
feat(parsers): add support for parsing mobi metadata headers
```

## 4. Отправка Pull Request

- Убедитесь, что ветка синхронизирована с актуальным `master`.
- Заполните шаблон Pull Request с кратким описанием изменений.
- Дождитесь прохождения автоматических проверок GitHub Actions CI.
